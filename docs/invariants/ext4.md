# Invariants: ext4 reader

Covers the ext2/3/4 reader `internal/filesys/ext4` and its builder `ext4test`. The rules every reader shares are under [filesystems](filesystems.md); deleted-file recovery is under [recovery](recovery.md). Part of the [forensic invariants](../invariants.md), which say how to add or change a row. Each row is enforced by the tests it names: keep them green.

| Invariant | Test |
|---|---|
| Filesystem readers match independent oracles from real images: for each committed `mke2fs`-built fixture the ext4 reader's live tree (exact path set, entry types, sizes, modes, mtimes, symlink targets, SHA-256 of every file's content) and the deleted names the generator removed equal the recorded expectations, and `Unallocated` equals exactly the free-block ranges `dumpe2fs` reports for every fixture, including the multi-group `meta_bg`+`flex_bg`+`uninit_bg` one (`ext4-1k-metabg-uninit`) (no free run overlaps live content or group metadata); the `ext4-xattr` fixture (`metadata_csum`, `ea_inode`; `debugfs ea_set` made its attributes) also lists exactly the attribute names `ea_list` reports for every file, and the value size and SHA-256 `ea_get` reports for the in-inode and xattr-block ones, with no warning; extra stale deleted records are logged, not asserted | `TestExt4MatchesOracle` |
| A checksum that fails is shown, never hidden: an ext4 xattr block is verified under `metadata_csum` with the crc32c checksum type (crc32c with the filesystem seed over the 64-bit block number and the block with `h_checksum` read as zero); a mismatch is a warning naming the block and both checksums (deduplicated by text, so a block shared by many inodes warns once), the attributes are still listed and returned, and each entry that uses the block carries `xattr_csum=bad` (the inode checksum is the separate `checksum=bad`). Without `metadata_csum`, or with another checksum type, no verdict is made. The xattr block of `ext4-xattr`, written by libext2fs (e2fsprogs 1.47), verifies, so the formula is checked against an independent implementation and not only against the builder; a block number above 2^32 is checked on a sparse builder image (`TestXattrBlockChecksumAbove32BitBlockNumber`) | `TestXattrBlockChecksumMismatchWarns`, `TestXattrBlockChecksumAbove32BitBlockNumber`, `TestXattrBlockChecksumSharedBuilderBlockWarnsOnce`, `TestXattrBlockChecksumVerified`, `TestXattrBlockChecksumIgnoredWithoutMetadataCsum`, `TestXattrBlockChecksumUnsupportedType`, `TestXattrBlockForgedHeaderNeverPanics`, `FuzzExt4Open` |
| Nothing is allocated from a declared EA-inode value size: an ext4 xattr value held in an EA inode is opened as a streaming file of the EA inode's real image runs (the EA inode is read without its own attributes, so a loop of EA inodes cannot recurse). It must carry the EA-inode flag, be a regular file whose i_size equals the entry's e_value_size, stay within 16 MiB and be fully mapped by blocks; any mismatch is `ErrCorrupt` for that value, never an empty value. The value's crc32c (filesystem seed) is checked against the EA inode's `i_atime` (confirmed on the libext2fs-written `ext4-xattr` fixture); a mismatch is a warning and the bytes are still returned. The mismatch is a warning (once per EA inode) and the attribute is marked `value_hash_bad` in the `XattrReader` listing (`TestXattrReaderHashBadMarksOnlyThatAttribute`); the hash is computed once per EA inode and the hashed bytes are bounded per filesystem (`TestXattrReaderManyEntriesOnOneEAInodeReadItOnce`, `TestXattrReaderHashWorkIsBounded`), and the EA-inode back-reference (parent inode and generation) and the entry `e_hash` are not checked, so a value that passes its hash may not belong to this parent. A `system.data` value held in an EA inode is unsupported, not decoded | `TestEAInodeDeclaredSizeNeverAllocates`, `TestEAInodeValueIsRead`, `TestEAInodeRunsAreRealImageRuns`, `TestEAInodeSizeMismatchIsCorrupt`, `TestEAInodeWithoutFlagIsCorrupt`, `TestEAInodeNotARegularFileIsCorrupt`, `TestEAInodeHoleIsCorrupt`, `TestEAInodeCapIsEnforced`, `TestEAInodeHashMismatchWarns`, `TestEAInodeCycleTerminates`, `TestSystemDataInEAInodeIsUnsupported`, `FuzzExt4Open` |
| The ext4 `XattrReader` never offers a partial, invented or unverified-as-verified value. `Xattrs` re-reads the inode from `e.ID` alone (a forged `Size`, `Type`, `Attrs` or `Deleted` changes nothing; a `dirent:` ID is `ErrDeleted`) and lists the in-inode area then the xattr block: `Storage` is `inline` (no runs) or `stream` (a value in an EA inode, listed with the size the EA inode really has and the real image runs on open). A table that cannot be read is an error and a nil list, never an empty list and never the attributes before the damage; an EA inode that is damaged spoils its own attribute only (listed with size -1, `ErrCorrupt` on open); a name that is not valid UTF-8 or holds a NUL is the shared `~raw~` alias of the stored name; two attributes of one name are `ErrAmbiguous`, an unknown name `ErrNotFound`; more than 4096 attributes is `ErrXattrCap`. A value that was hashed and matches is `value_hash_ok`; an empty `Integrity` means "not checked" and is never read as verified. A value whose hash fails is marked `value_hash_bad` on that attribute alone (the bytes are still returned, one warning per EA inode). The hash verdict (a bad hash, or a value that cannot be read) is computed once per EA inode and kept, so a failed read is charged to the bound once (`TestXattrReaderUnreadableValueIsChargedOnce`) and many entries naming one EA inode read its value once, and the value bytes hashed per filesystem are bounded (512 MiB): past the bound the attribute is `value_hash_unchecked` with size -1 and `OpenXattr` is `ErrLimit`, never a value passed unchecked | `TestXattrReaderListsAllStorages`, `TestXattrReaderStreamRunsAreRealRuns`, `TestXattrReaderRawNameAlias`, `TestXattrReaderCorruptTableIsAnError`, `TestXattrReaderDamagedValueFailsOnlyThatAttribute`, `TestXattrReaderHashBadMarksOnlyThatAttribute`, `TestXattrReaderManyEntriesOnOneEAInodeReadItOnce`, `TestXattrReaderHashWorkIsBounded`, `TestXattrReaderUnreadableValueIsChargedOnce`, `TestXattrReaderDuplicateNameIsAmbiguous`, `TestXattrReaderCapIsTyped`, `TestXattrReaderDeletedIDIsErrDeleted`, `TestXattrReaderIgnoresForgedEntryFields`, `TestXattrReaderViaFilesysAs`, `FuzzExt4Open` |
| ext4 deleted directory entries are listed and flagged `Deleted` (listing gives names only; the content is recovered by `image recover`, see the ext4 recovery rows in [recovery](recovery.md)), and a stale htree copy of a live record is flagged `stale_copy=true`, never presented as live | `TestReadDirFlagsDeletedEntries`, `TestStaleCopyOfLiveRecord` |
| In any ext4 directory `Lookup` never says not found about a directory it did not read to the end; in a casefold directory it scans the whole directory and decides in one order: an exact byte match, the `~raw~` alias, the incomplete-scan error (`filesys.ErrLimit` for the record cap, else a corruption error matching `filesys.ErrIncomplete`, when the scan did not read the whole directory: cap, damaged or unreadable block, a record whose name_len does not fit, a tail too short for a record, damaged map, sparse hole, `i_size` above 64 MiB; a checksum-bad block is not a cut), exactly one name the kernel's comparison calls the same, `ErrAmbiguous` for two or more (naming the first two and counting the others, keeping at most two records), `ErrUndecided` when a stored name has a shape the comparison was not measured for and nothing above decided (never `ErrNotFound`; the command line exits non-zero with a message saying so and a batch path never skips it), not found; two records whose bytes are the alias with no exact match are `ErrAmbiguous`; an exact or alias name stands even when an earlier block is damaged; `.` and `..` are never folded, an encrypted directory is exact-only, a component over 255 bytes is absent, and a volume whose `s_encoding`/`s_encoding_flags` is not implemented gives `ErrUnsupported` on a miss; every row of `kernel-vectors.json.gz` resolves in the committed `ext4-casefold` image as the kernel resolved it (the image is checked by these tests, not by `TestExt4MatchesOracle`) | `TestCasefoldLookupMatchesKernel`, `TestCasefoldFixtureTreeEqualsOracle`, `TestCasefoldExactBeatsFold`, `TestCasefoldAliasBeatsFold`, `TestCasefoldAliasBeatsASingleFoldHit`, `TestCasefoldAmbiguousIsAnError`, `TestCasefoldExactAfterManyFoldHitsWins`, `TestCasefoldAliasLastStillBeatsFold`, `TestCasefoldAmbiguityScanIsBounded`, `TestCasefoldUnknownShapeIsUndecidedNotNotFound`, `TestCasefoldUnknownEncodingIsUnsupported`, `TestCasefoldNeverFoldsEncryptedOrDots`, `TestCasefoldInvalidUTF8ComparesBytes`, `TestCasefoldExactAndAliasStandOnADamagedEarlierBlock`, `TestCasefoldLookupIsBounded`, `TestCasefoldTwoAliasRecordsAreAmbiguous`, `TestCasefoldIncompleteScanBeatsFoldDecision`, `TestCasefoldExactBeforeCutStillWins`, `TestCasefoldExactAndAliasAfterTheCutStillWin`, `TestLookupAfterCapIsAnError`, `TestLookupAtExactlyTheCapIsNotCut`, `TestLookupInDamagedBlockIsAnError`, `TestLookupAfterUnreadableBlockIsAnError`, `TestLookupAfterDamagedMapIsAnError`, `TestLookupInSparseDirectoryIsAnError`, `TestLookupAfterBadNameLenIsAnError`, `TestLookupInOversizeDirectoryIsAnError`, `TestLookupBadChecksumBlockIsStillSearched`, `TestLookupErrorIsNotCached`, `TestLookupCutErrorNamesTheCause`, `TestEveryDirectoryCutCauseLogsItsWarning`, `TestDirectoryMapEndingShortIsACutAndWarns`, `TestExitCodeOfAnIncompleteLookup`, `TestImageUndecidedLookupExitsNonZeroWithAClearMessage`, `TestExtractOfAnUndecidedLookupFailsTyped`, `TestExtractOfAnUndecidedOpenIsNotSkipped`, `TestExtractPathLookupFailureIsAudited`, `TestRecoverPathLookupFailureIsAudited`, `FuzzExt4CasefoldLookup`, `TestImageCutDirectoryExitsNonZeroAndIsAudited` |
| An ext4 file cut by a truncated image opens with the bytes the image holds: an extent (or block-map pointer, or index node) between the image end and the declared block count ends the walk, the whole blocks before it are the trusted prefix (`Runs()` is that prefix, nil when nothing is covered), the warning says how many bytes are readable and at least how many more are mapped after the cut (counted in the cut extent's node only; it says when other nodes were not examined or the count stopped at a damaged entry, and that the count may be incomplete), and every read at or beyond the prefix is `ErrCorrupt`, never zeros; an extent beyond the declared filesystem or any other damaged map is still corrupt and fails to open, and an uninitialized extent within the declared filesystem is a hole | `TestTruncatedImageKeepsExtentPrefix`, `TestTruncatedImageBlockMapPrefix`, `TestTruncatedImageCutInsideIndexNode`, `TestTruncatedImageHoleBeforeCutIsKept`, `TestUninitExtentInsideDeclaredButBeyondImageIsAHole`, `TestTruncatedImageFirstBlockCutHasNoRuns`, `TestTruncatedImageWarningNamesTheLoss`, `TestTruncatedWarningUnderIndexNodeSaysCountMayBeIncomplete`, `TestTruncatedWarningCountStopsAtADamagedEntry`, `TestTruncatedFixtureEqualsUntruncatedPrefix`, `TestExtentBeyondDeclaredFilesystemStaysCorrupt`, `TestOtherDamagedMapsStillFailToOpen`, `TestTruncatedPrefixNeverAllocatesFromSize`, `TestCutDoesNotLoop`, `TestFuzzTruncatedSeedsCarryPrefixes`, `FuzzExt4Open`, `TestExtractExt4TruncatedImageIsIncomplete`, `TestExtractExt4CutAtFirstBlockIsNeverComplete` |
