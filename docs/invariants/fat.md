# Invariants: FAT and exFAT readers

Covers the FAT12/16/32 reader `internal/filesys/fat`, the exFAT reader `internal/filesys/exfat` and their builders. The rules every reader shares are under [filesystems](filesystems.md); deleted-file recovery is under [recovery](recovery.md). Part of the [forensic invariants](../invariants.md), which say how to add or change a row. Each row is enforced by the tests it names: keep them green.

| Invariant | Test |
|---|---|
| The FAT12/16/32 reader equals an independent oracle for each committed `mkfs.fat`+`mtools`-built fixture (`fat12`, `fat16`, `fat32`; oracle from the source tree, the generator's own deletions, `fsck.fat -v` and `mshowfat`): the image's sha256 equals the oracle's `generator.image_sha256` (a stale oracle fails); `Info` (type, label, volume id, cluster size, size) equals the oracle with no warnings; the live tree is exactly the oracle's path set (none missing, none extra) with the oracle's entry types and modified times (to 2 s, local time, `ZoneKnown` false); every file's size, SHA-256 and `File.Runs` equal, in file order (compared as returned: not sorted, only adjacent clusters merged), the cluster chain `mshowfat` follows (cut at the file size; the oracle must hold a fragmented file); every deleted name the generator removed is reported `Deleted` (extra deleted records are logged, not asserted); and `Unallocated` equals exactly the free clusters, those no live chain holds (the generator fails unless their count equals the in-use count `fsck.fat` reports): the same runs, a total of free count x cluster size, no run overlapping a live file | `TestFATMatchesOracle` |
| The exFAT reader equals an independent oracle for the committed `mkfs.exfat`-built fixture (oracle from the source tree, the generator's own deletions and `dump.exfat`): the same checks as the FAT row (image sha256 pinned, `Info` with no warnings and no `volume dirty`/`media failure` feature, exact live path set, types, sizes, SHA-256, per-file runs equal, in file order, to the chain `dump.exfat` reports, deleted names reported), except that modified times are exact to the second with `ZoneKnown` true (a valid UTC offset), and `Unallocated` equals exactly the free clusters, those no chain, bitmap, up-case table or root directory holds (the generator cross-checks their count against `dump.exfat`'s `Free Clusters`) | `TestExfatMatchesOracle` |
| An exFAT file whose chain is shorter than `DataLength` opens with the clusters that can be trusted (an `Info` warning; the rest reads as a corrupt-chain error, never zeros, and the `ValidDataLength` hole is shown only for a whole chain); declared-size inconsistencies still fail `Open`; `extract` keeps the prefix flagged `incomplete` with its runs | `TestExfatShortChainOpensWithPrefix`, `TestExfatChainIntoBadEntryOpensWithPrefix`, `TestExfatNoFatChainPastTruncatedImageOpensWithPrefix`, `TestExfatTruncatedFixtureEqualsUntruncatedPrefix`, `TestExfatPrefixHoleRule`, `TestExfatInvalidFirstClusterStillCorrupt`, `TestExtractExfatShortChainIsIncomplete`, `TestExtractExfatTruncatedImageIsIncomplete` |
| exFAT name lookup never says not found about a directory not read to the end or a name it could not read, never folds without the volume's up-case table, and decides in one order (exact, canonical `~raw~` alias, incomplete-scan error, undecided unreadable name, one fold hit, `ErrAmbiguous`, undecided no-table same-length name, not found); a cut listing returns its entries with an `ErrIncomplete` error | `TestExfatLookupInDamagedChainIsAnError`, `TestExfatLookupInOversizeDirectoryIsAnError`, `TestExfatReadDirOfDamagedChainReturnsEntriesAndError`, `TestExfatLookupCutErrorSaysCannotBeDecided`, `TestEveryDirectoryCutCauseLogsItsWarning`, `TestExfatLookupWithoutUpcaseTableIsUndecided`, `TestExfatLookupTruncatedNameNeverMatches`, `TestExfatLookupUnreadableNameMakesAMissUndecided`, `TestExfatLookupStoredNameThatIsAnotherRecordsAliasIsAmbiguous`, `TestExfatLookupFoldAmbiguousIsAnError`, `TestExfatLookupManyFoldCollisionsIsAmbiguous`, `TestExfatLookupInDamagedDirectorySetIsNotAbsent`, `TestImageCutExfatDirectoryExitsNonZeroAndIsAudited`, `TestImageExfatUndecidedLookupExitsNonZero`, `FuzzExfatOpen` |
| An exFAT name whose `NameHash` does not match is shown, never hidden or trusted silently: `name_hash=bad` plus a warning; an unverifiable one is `name_hash=unverified`, never presented as verified; both committed real images verify in full | `TestExfatNameHashSpecVector`, `TestExfatNameHashMismatchFlagsTheEntry`, `TestExfatNameHashDeletedSetChecked`, `TestExfatNameHashUnverifiedWithoutUpcaseTable`, `TestExfatNameHashTruncatedNameUnverified`, `TestExfatNameHashVerifiesOnRealFixtures` |
| exFAT reads the FAT and bitmap `ActiveFat` names and never the stale copy; a missing active bitmap reports no free space; the inactive copies are compared in bounded chunks and a difference is a warning | `TestExfatTexFATSecondActiveIsRead`, `TestExfatTexFATFirstActiveReadsFirst`, `TestExfatTexFATMissingActiveBitmapReportsNoFreeSpace`, `TestExfatActiveFatWithOneFATWarns`, `TestExfatTexFATDifferingCopiesWarn`, `TestExfatTexFATFeatureReported`, `TestExfatTexFATCompareIsBounded` |
| FAT and exFAT deleted entries are listed and flagged `Deleted` (names only, no content; `Open` of one is `ErrDeleted`). A FAT long name recovered from the slots of a deleted entry carries `lfn=recovered`, plus `lfn_tail=unterminated` when slot reuse may have truncated it, so it is never presented as a verified name | `TestReadDirFlagsDeletedEntries`, `TestDeletedLongNameRecoveryMarkers`, `TestExfatDeletedSetFlagged` |
| A FAT file whose cluster chain is shorter than its size opens with the clusters that can be trusted (an `Info` warning; the tail reads as a corrupt-chain error, never as zeros), and `extract` keeps that prefix as an artifact flagged `incomplete` with the runs of that prefix recorded | `TestFileChainShorterThanSize`, `TestExtractFATShortChainIsIncomplete` |
| A FAT lookup never says not found about a directory it did not read to the end, and a FAT listing that was cut is never presented as complete: the entries read come with an error matching `filesys.ErrIncomplete` (`ErrLimit` for the entry cap, the chain bound and the budget; a corruption error for a damaged chain or a failed read); damage after the end marker is not a cut; the walkers keep the entries | `TestLookupAfterCapIsAnError`, `TestLookupAtExactlyTheCapIsNotCut`, `TestLookupInDamagedChainIsAnError`, `TestLookupAfterUnreadableClusterIsAnError`, `TestLookupAfterBudgetCutIsAnError`, `TestLookupDamageAfterEndMarkerIsNotACut`, `TestReadDirOfCutDirectoryReturnsEntriesAndError`, `TestResolveDirBehindCutListingIsNotNotFound`, `TestResolveDirDescendsThroughACutListing`, `TestEntryIDBeyondACutIsNotNotFound`, `TestBudgetSpentBeforeFirstEntryStaysCorruptOnly`, `TestEveryDirectoryCutCauseLogsItsWarning`, `TestWalkDescendsIntoACutFATDirectory`, `TestImageCutFATDirectoryExitsNonZeroAndIsAudited`, `FuzzFATOpen` |
| FAT name lookup is decided over the whole directory in the order exact (long or 8.3 name), canonical `~raw~` alias (through `filesys.RawNameAlias`/`DecodeRawNameAlias`, only for names shown in that form), incomplete-scan error, one fold hit, `ErrAmbiguous` (two fold hits, two exact or two alias records, or a stored name that is another record's alias), not found; at most two candidates are kept; on a cut scan only an exact name is answered | `TestRawNameDisplayIsTheSharedAlias`, `TestLookupAliasRejectsNonCanonicalSpelling`, `TestLookupAliasNeverStandsForAPlainName`, `TestLookupStoredNameThatIsAnotherRecordsAliasIsAmbiguous`, `TestLookupTwoAliasRecordsAreAmbiguous`, `TestLookupTwoExactRecordsAreAmbiguous`, `TestLookupFoldAmbiguousIsAnError`, `TestLookupExactAfterFoldHitsWins`, `TestLookupAliasAfterFoldHitsWins`, `TestLookupShortNameIsAnExactName`, `TestLookupExactStandsOnACutScan`, `TestLookupFoldHitOnACutScanIsIncomplete`, `TestCutLookupReturnsOnlyAnExactMatch`, `TestLookupManyFoldCollisionsIsAmbiguous`, `TestFATLookupResolvesEveryOraclePath` |
