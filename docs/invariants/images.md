# Invariants: images, import and extraction

Covers `internal/image` (raw and EWF/E01), `internal/volume`, `image import`, `image info` and `image extract` in `internal/examine`, and the provenance of derived artifacts. Part of the [forensic invariants](../invariants.md), which say how to add or change a row. Each row is enforced by the tests it names: keep them green.

| Invariant | Test |
|---|---|
| Image analysis never modifies source evidence: the parent artifact is opened read-only via `Case.OpenArtifact`, and its hash is unchanged after info/ls/stat/extract/unalloc | `TestExamineNeverModifiesSource`, `TestExtractNeverModifiesSource`, `TestOpenArtifactReadOnly` |

| E01 (EWF v1) chunks are never served unless proven: a chunk whose zlib stream or Adler-32 fails, whose zlib output is not exactly one chunk (output is capped at the chunk size, so a decompression bomb is refused), whose entry points outside its segment, or that does not fit inside its sectors section, is a `*ChunkError` wrapping `ErrChunkCorrupt` (chunk index, segment, offset), never zeros: `ReadAt` returns the bytes before the bad chunk together with the error, leaves the rest of the caller's buffer untouched, repeats the same error on a re-read, and the neighbouring chunks still read. A real I/O error of the segment source is NOT chunk corruption: it is returned wrapped (the message names the chunk) and is neither a `*ChunkError` nor `ErrChunkCorrupt`, `Verify` returns it as the run error (no bad chunk is blamed; `VerifyContainer` audits `result` `error`) and `extract` ends the analysis with `analysis.error` instead of keeping a prefix and going on, so a transient disk fault never looks like damage to the evidence; a segment that shrinks after `Open` is still a `*ChunkError` wrapping `io.ErrUnexpectedEOF` | `TestEWFCorruptChunkIsError`, `TestEWFBadZlibStreamsAreChunkErrors`, `TestEWFZlibOutputCappedAtChunkSize`, `TestEWFChunkOffsetOutsideSegmentIsChunkError`, `TestEWFUncompressedChunkBoundedToItsSectorsSection`, `TestEWFSegmentReadErrorIsWrapped`, `TestExtractIOErrorIsNotDowngradedToIncompleteFile` |
| E01 chunk tables are trusted only when they provably number their chunks. A table (or its `table2` copy) is used only if it directly follows its sectors section, its first entry is the sectors payload start, its entries strictly increase and every one lies inside the sectors section payload (plus its own header and entries Adler-32 and counts). When the table fails, `table2` is the fallback; when both fail (or no table follows a sectors section, or a middle table is missing) that group and EVERY chunk from its first index onward are unreadable (`ErrChunkCorrupt`, one warning naming the group and the rule), earlier chunks stay byte-exact and the image still opens (a damaged table never makes the whole image unopenable); when both copies are valid but differ, the copy whose entries footer verified wins and equally trusted copies make only the differing chunks unreadable (when the two copies disagree on the entry COUNT, every chunk from the shorter count onward is unreadable; a table group beyond the volume's chunk count is uncovered with a warning while the volume's own chunks read); a later group is never attached to guessed indexes | `TestEWFTable2FallbackWhenTableCorrupt`, `TestEWFMissingTableMakesLaterChunksUnreadable`, `TestEWFHostileTable`, `TestEWFDisagreeingTablesNeverServeUnprovenChunks`, `TestEWFTablesDifferFooterDecides`, `TestEWFTableCountMismatch` |
| A compressed E01 chunk whose span also holds the start of another zlib stream (header check bits valid, method 8, no preset dictionary, at least 6 bytes) is a chunk error naming the skipped stored chunk, so a checksum-consistent forged table that drops a compressed chunk is found at the chunk before the drop on read and by `Verify` (`unverified`, that chunk), while a few padding bytes after a stream stay a warning; legal builder layouts open with no warning | `TestEWFDroppedCompressedChunkIsFoundOnRead`, `TestEWFZlibStartsAt`, `TestEWFDecodeAcceptsEveryBuilderLayout`, `TestEWFBytesAfterZlibStreamWarn` |
| The E01 section walk is bounded, so hostile structure never costs unbounded time or memory: a descriptor chain that loops, goes backwards or fails its Adler-32 is a corrupt-container error; each section payload is bounded by the next section (100000 overlapping descriptors open in bounded time and memory) and per-kind section counts are capped; a segment set with the wrong order or numbering (swapped segments, a missing middle segment) does not open | `TestEWFSectionWalkLoopIsCorrupt`, `TestEWFOverlappingDescriptorsAreBounded`, `TestEWFSectionCountCapsPerSegment`, `TestSectionDescriptorChecksum`, `TestSegmentsOutOfOrder`, `TestMissingMiddleSegment`, `TestSegmentCountAndSizeLimits` |
| An incomplete E01 set is opened, never silently treated as whole: a last segment with no `done` section, a chain ending without a terminal section, or a missing LAST segment opens with the warning "E01 set incomplete" (a missing segment also "chunk table covers X of Y chunks"); a last segment truncated mid-section keeps the sections walked before the cut (warning "segment N truncated at offset X"); every chunk those sections do not cover reads as `ErrChunkCorrupt`, never zeros, while covered chunks stay byte-exact; a truncated NON-last segment is a corrupt-container error | `TestNoDoneIsIncomplete`, `TestNextInLastSegmentIsIncomplete`, `TestChainEndingAtEOFWithoutTerminal`, `TestEWFWalkPastEOF`, `TestEWFTruncatedRealFixture` |
| E01 `ReadAt` follows the `io.ReaderAt` contract and returns the media byte for byte for every compression, sector size, chunk size, table layout and segment count tried; the reader is safe for concurrent use, chunks are cached as immutable slices callers cannot alias, and after `Close` reads fail with `fs.ErrClosed`. The E01 concurrency tests run under `-race` in the race gate (step 2, `internal/image/...`; passed 2026-10-08, 0 data races); the fast check runs them without `-race` | `TestEWFReadAtContract`, `TestEWFReadAtMatchesMedia`, `TestEWFReadAtEmptyMedia`, `TestEWFConcurrentReadAt`, `TestEWFCachedChunksAreNotAliasedToCallers`, `TestEWFCacheLRU`, `TestEWFReadAfterClose` |
| E01 reads of the committed `ewfacquire`-built fixtures equal an independent oracle (`ewf_inspect.py`, which decodes every section and every chunk itself, cross-checked by `ewfverify`, `ewfinfo` and `ewfexport -f raw`): the raw disk's sha256 equals the oracle's `generator.image_sha256` and `raw.sha256` (a stale oracle fails first); each segment's sha256, the geometry, every section's type, offset, next and size, the header fields and the stored MD5/SHA-1 equal the oracle with zero warnings; the chunks the tables mark compressed equal the oracle's chunk-kind string for every variant (`single-none`, `single-best`, `multi-none` with 5 segments, `seed-small`); a whole-image `ReadAt` (and 300 random reads) equals the raw disk byte for byte and the media hashes equal the stored ones; `Verify` reports `match`; flipping one byte in the first compressed and the first uncompressed chunk (offsets from the oracle) makes exactly that chunk `ErrChunkCorrupt` with the oracle's index while the chunk before it still reads | `TestEWFFixtureRawDiskIsTheOracles`, `TestOpenRealFixtureSections`, `TestEWFFixtureChunkKinds`, `TestEWFReadAtMatchesRawFixture`, `TestVerifyRealFixtures`, `TestEWFFixtureFlippedByteIsChunkCorrupt` |
| `image info --verify` on an E01 image recomputes MD5 and SHA-1 over the whole media, compares them with the hashes the acquirer stored and ALWAYS appends exactly one hash-chained `image.verify` audit entry (`parent_id`, `parent_path`, `parent_sha256`, every segment `{id, sha256}`, `format`, `size`, `bytes_hashed`, `md5` and `sha1` each with `stored`, `computed` and `status`, `result`, `first_bad_chunk` when a chunk is unreadable, `error` when the run itself failed; a hash whose stored section is damaged also carries `reason`), also for a mismatch, an unreadable chunk, a cancel and a recovered panic. A plain `image info` appends no `image.verify`; a raw or split-raw image (it stores no hashes) gets a note, exit 0 and no audit entry. Results: `match`, `mismatch` (a stored hash differs from the computed one), `absent` (nothing stored and no hash section damaged), `unverified` (an unreadable chunk or a partial run: nothing is compared and `computed` is empty; and a stored-hash section that is present but fails its checksum or is too small to parse: that hash is never reported absent, its `stored` is empty, its `status` is `unverified`, its `reason` says "stored hash section damaged ...", the computed hash is still reported and the command exits 1; a hash another valid section still stores is unaffected), and, when the run did not finish, `cancelled` or `error`. Verification never modifies the source artifact (its size, mtime and sha256 equal the manifest, `case verify` stays OK) | `TestVerifyMatch`, `TestVerifyMismatchAndUnverified`, `TestVerifyAbsentHashes`, `TestVerifyDamagedHashSectionIsUnverifiedNotAbsent`, `TestVerifyPartialIsUnverifiedWithoutStoredHashes`, `TestVerifyCancel`, `TestVerifyContainerAuditsResult`, `TestVerifyContainerMismatchAudited`, `TestVerifyContainerUnreadableChunkAudited`, `TestVerifyContainerCancelAudits`, `TestVerifyContainerRecoversPanic`, `TestVerifyContainerRawIsNotVerifiable`, `TestVerifyContainerNeverModifiesSource`, `TestImageVerifyAuditsResult`, `TestImageVerifyDamagedHashSectionIsUnverifiedExits1`, `TestImageInfoWithoutVerifyAppendsNothing`, `TestImageVerifyRawAppendsNothing` |
| `image info --verify` exit codes: `match` and `absent` exit 0; `mismatch` exits 4 (the result is printed first), also when the audit append that follows fails (the integrity signal is never masked; the audit failure is reported on stderr); `unverified`, a cancel, a recovered panic (stored hashes printed as `unknown`) and a failed audit append of an otherwise good result exit 1, with the result already printed | `TestImageVerifyMismatchExits4`, `TestImageVerifyUnreadableChunkExits1`, `TestImageVerifyCancelledExits1AndIsAudited`, `TestImageVerifyPanicShowsStoredHashesUnknown`, `TestVerifyOutcomeMismatchSurvivesAuditFailure`, `TestVerifyContainerAuditFailureIsReturnedWithResult` |
