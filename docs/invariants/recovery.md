# Invariants: recovery, carving and slack

Covers deleted-file recovery (`image recover`, each reader's `Recoverer`), carving (`internal/carve`, `image carve`), slack (`image slack`) and the R-series checks of `case verify`. Part of the [forensic invariants](../invariants.md), which say how to add or change a row. Each row is enforced by the tests it names: keep them green.

| A deleted entry is never opened and never extracted as a live file, whatever recovery maps its filesystem holds. `Recoverable` (the optional `filesys.Recoverer`, reached through `filesys.As`/`SupportsRecovery`, never a type assertion) returns candidates for a listed deleted entry, and `Open` of that entry, with `Deleted` true or forged false, is still `ErrDeleted` with no file; `extract -r` writes no artifact for a deleted entry that has recovery maps and its `analysis.warning` points at `image recover` (recovery is `image recover` only) | `TestOpenDeletedStillErrDeleted`, `TestExtractStillSkipsDeleted` |
