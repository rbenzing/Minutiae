# Invariants: filesystem readers (shared rules)

Covers the rules every reader of `internal/filesys` shares: detection (`filesys/detect`), entry IDs, names and casefolding (`filesys/utf8fold`), warnings, hostile input and the real-image fixtures. Each reader also has its own file: [ext4](ext4.md), [FAT and exFAT](fat.md), [F2FS](f2fs.md), [HFS+](hfsplus.md) and [APFS](apfs.md); deleted-file recovery is under [recovery](recovery.md). Part of the [forensic invariants](../invariants.md), which say how to add or change a row. Each row is enforced by the tests it names: keep them green.

| Invariant | Test |
|---|---|
| Hostile images never panic the process: panics in container, partition-table and filesystem parsers are recovered into errors, and the parsers are fuzzed (the carving scanner too: `FuzzCarve` scans arbitrary bytes split into two runs with the built-in set, with and without nesting and at any alignment, and fails on a panic, a hit outside its run or past its type's `MaxLen`, any `OutsideReads`, or validator reads beyond the budget plus 64 KiB; its seeds are `testdata/fuzz/FuzzCarve`, builder outputs and real objects covering all fifteen validators, and `TestFuzzCarveSeedsRun` runs them under plain `go test`; `TestBuilderCorpusCoversEveryValidator` pins that the corpus they are built from holds every validator and a JPEG XL container). `FuzzFATOpen`, `FuzzExfatOpen`, `FuzzF2FSOpen` and `FuzzHFSPlusOpen` call the readers directly (not through `detect`, so a panic fails the fuzz) on arbitrary bytes, seeded with builder images (FAT12/16/32, exFAT, F2FS or HFS+/HFSX, long and deleted names, fragmented chains, odd sector sizes; for HFS+ 15 builder images covering multi-level catalogs, hard links, overflow extents, attributes, compressed files, wrappers and a journal) and the trimmed real fixtures (all six HFS+ ones), and run `Open`, a bounded `Walk` (5000 entries), `Open` plus a bounded read of every file (each `File.Runs` must pass `filesys.CheckRuns`, or, when it covers less than the size, be a valid prefix (`filesys.CheckRunsPrefix`) with a read at the prefix end failing with `ErrCorrupt`) and `Unallocated` (every run must lie inside the filesystem); `TestOpenHostileBPB`, `TestDirHostile` (FAT and F2FS) and `TestExfatHostile` cover crafted hostile structures, and for F2FS also `TestOpenHostileGeometry`, `TestInodeHostile` and `TestSITJournalHostile`; for HFS+ `TestBTreeHeaderHostile` (25 forged B-tree header and extents-header cases, each a `CorruptError`; the 21 header-field cases after reading less than 64 KiB, the three node-0 cases and the extents-header case at `Open` without that bound), `TestDirHostile` (valence lie, ancestor loops, a thread parent loop, name past its record, junk records, a million junk records costing a bounded directory budget), `TestAttributesHostile` (oversized or short attribute records, names past the key, a 5000-record run, a damaged attributes tree), `TestOpenHostileGeometry` (20 forged volume-header and fork-geometry cases, plus truncated and wrapped volumes as subtests) and `TestFuzzBuilderSeedsOpen`/`TestFuzzFixtureSeedsOpen` (every builder seed opens with no warning; the trimmed real-fixture seeds open clamped to the image, with the truncated-image warning, and are only required to open); `FuzzEWFOpen` opens 1-3 segments of arbitrary bytes (seeded with builder images using most builder options (not the set id, SHA-1 override or header text variants), empty media, a bare segment header and the trimmed real fixture) and runs `Metadata`, `Warnings`, sequential and derived-offset reads up to 8 MiB plus tail, end-of-media and past-end reads, each held to the `io.ReaderAt` contract and re-read for determinism, plus a negative-offset read (no panic is all it asserts), then a `Verify` cancelled after 8 MiB whose result must be self-consistent; `TestVolumeHostile` (E01 volume section: bad sector size, chunk size, overflow, chunk-count disagreement, checksum, unsupported layout), `TestEWFHostileTable` and `TestOpenSurvivesMutations` (1500 mutated images, no panic, no hang) cover crafted hostile E01 structures; `FuzzExt4Recoverable` and `TestRecoverableHostileStaleMaps` cover the ext4 recovery reader on forged IDs and hostile stale inodes, maps and leaves | `TestDetectRecoversPanic`, `TestSessionRecoversFSPanic`, `TestOpenRecoversContainerAndTablePanics`, `FuzzRead`, `FuzzOpen`, `FuzzExt4Open`, `FuzzFATOpen`, `FuzzExfatOpen`, `FuzzF2FSOpen`, `TestOpenHostileBPB`, `TestDirHostile`, `TestExfatHostile`, `TestOpenHostileGeometry`, `TestInodeHostile`, `TestSITJournalHostile`, `FuzzHFSPlusOpen`, `TestBTreeHeaderHostile`, `TestAttributesHostile`, `TestFuzzBuilderSeedsOpen`, `TestFuzzFixtureSeedsOpen`, `FuzzEWFOpen`, `TestVolumeHostile`, `TestEWFHostileTable`, `TestOpenSurvivesMutations`, `FuzzExt4Recoverable`, `TestRecoverableHostileStaleMaps` |
| Filesystem detection is not fooled by stale or forged signatures, and a damaged volume does not end the search. `f2fs.Probe` matches a valid PRIMARY superblock only (magic, major_ver 1, 4 KiB blocks at byte 1024); a stale or forged F2FS backup superblock planted at byte 4096+1024 of a real ext4 (4 KiB), ext2 (1 KiB), FAT12/16/32 or exFAT image does not change which driver claims it or what it opens as (the last-resort `f2fs-backup` driver, `f2fs.ProbeBackup`, is registered after every other driver and matches only a valid backup with an invalid primary); an F2FS image with a destroyed primary is claimed by exactly that driver and opens as `f2fs` (Info type, backup-in-use warning) through the backup. When the first matching driver's `Open` fails with an error wrapping `ErrCorrupt` (a panicking `Open` counts), `detect.OpenWith` and `examine`'s per-driver loop try the remaining drivers whose `Probe` matches: the first that opens wins and the failure is kept as a warning/partition note (`driver X matched but failed to open: <err>; opened as Y`), when none opens the first failure is the error, and any other error (I/O) stays final. `hfsplus.Probe` checks only a valid PRIMARY volume header (the embedded one for a wrapper), independently of FAT: a stale or planted HFS+ header inside a FAT12/16/32 image may be claimed first, but when the catalog it names lies inside the image and is not a B-tree header node the HFS+ `Open` fails and detection falls through to the FAT driver with the usual `driver X matched but failed to open` note, so it does not change what the image opens as (a planted header whose catalog lies beyond the end of the image is accepted as a truncated volume: the `also matched by: fat` note is then the only signal); in an exFAT image the exFAT driver (probed before HFS+) claims it and the result carries `also matched by: hfsplus`, with no fall-through to FAT; a stale FAT boot sector in a real HFS+ volume's boot blocks does not hide HFS+. When more than one driver's `Probe` matches a partition, the opened result carries the note `also matched by: <drivers> (ambiguous signatures)`, shown in the partition notes of `image info`; the HFS+ driver sits after exFAT and before FAT and the APFS driver first of all (see the APFS signature row); the last-resort `f2fs-backup` driver is never reported as an ambiguous claimant | `TestStaleF2FSBackupSuperblockDoesNotHideOtherFilesystems`, `TestF2FSDestroyedPrimaryOpensThroughBackupDriver`, `TestDetectOpensHFSPlus`, `TestPlantedHFSPlusHeaderFallsThroughToFAT`, `TestStaleFATBootSectorDoesNotHideHFSPlus`, `TestOpenChecksTheCatalogHeaderNode`, `TestOpenWithReportsAmbiguousSignatures`, `TestInfoReportsAmbiguousSignatures`, `TestInfoHasNoAmbiguityNoteWhenClean`, `TestDriversClaimExactlyTheirOwnImages`, `TestProbe`, `TestProbeRequiresSupportedGeometry`, `TestOpenWithFallsThroughOnCorruptOpen`, `TestInfoStaleF2FSBackupDoesNotHideFAT`, `TestInfoF2FSDestroyedPrimaryOpensThroughBackup`, `TestInfoFallsThroughCorruptOpenToLaterDriver`, `TestInfoCorruptOpensAllFailAndNonCorruptIsFinal` |
| Casefold comparison equals the kernel's: every row of `kernel-vectors.json.gz` (probes derived by an independent script from the Unicode 12.1.0 files, verdicts from a real kernel in a QEMU guest, ext4 and F2FS agreeing on all 15988) is reproduced by `utf8fold.Equal` in both directions (`Same` is same, `Different` is different, always decided); the tables are regenerated byte for byte from the committed inputs; a name that is not valid UTF-8 follows the MEASURED rule and only the shape combinations that a vector row shows are decided (one composite label per name: the text before an invalid tail, where the stray bytes sit and the tail form together; a stray continuation byte after the first byte is text; one or two stray bytes first, or a listed invalid tail at the end, make the name opaque, compared byte for byte; U+FFFE, U+FFFF and U+10FFFF are ordinary); every other shape, the empty name and a name over 255 bytes is `Unknown`, never `Different`, never "not found" and never folded by a guess | `TestKernelVectors`, `TestTablesAreUpToDate`, `TestEveryDecidedShapeIsShownByAVector`, `TestClassifyMatchesTheMeasuredRule`, `TestEqualBothOrdersForEveryKindPairing`, `TestEqualEmptyNameIsUnknown`, `TestKeyRejectsInvalidUTF8`, `TestHostileUnmeasuredShapeIsUndecided`, `TestKeyNeverAllocatesFromContent`, `FuzzKey` |
| The `~raw~` display form of a name has one definition (`filesys.RawNameAlias`) and one canonical decoder (`filesys.DecodeRawNameAlias`); ext4, F2FS, FAT and exFAT use them, accept exactly one spelling per name (no padding, no embedded CR/LF, no trailing bits, no empty payload) and, in a plain directory, let the alias stand only for names `ReadDir` shows in that form (this replaces the earlier ext4 behaviour of matching any name equal to the decoded bytes); the `~enc~` form is the same encoding behind another prefix and is decoded by the same function; a stored name that is also the display form of another record is `ErrAmbiguous` in ext4, F2FS, FAT, exFAT, APFS and HFS+ (the incomplete-scan error when the scan was cut), never the stored name | `TestDecodeRawNameAliasRoundTrip`, `TestDecodeRawNameAliasRejects`, `TestRawNameDisplayIsTheSharedAlias`, `TestLookupAliasRejectsNonCanonicalSpelling`, `TestLookupAliasNeverStandsForAPlainName`, `TestLookupAliasesAreCanonical`, `TestLookupAliasPreference`, `TestLookupStoredNameThatIsAnotherRecordsAliasIsAmbiguous`, `TestLookupStoredAliasShapedNameBeforeACutIsIncomplete`, `TestLookupEncAliasRejectsNonCanonicalForms` |
| Filesystem readers derive `Open`/`ReadDir` results from the disk via the `Entry` ID; caller-supplied `Entry` fields (`Size`, `Type`, `Deleted`, `Attrs` such as `first_cluster`, `valid_data_length`, `no_fat_chain`, ext4's `inode`) are never trusted: a forged field changes nothing, a deleted entry stays deleted and a directory stays a directory whatever the caller says (a deleted entry has its own deleted-record ID, such as `dirent:<block>:<offset>`, so `Deleted` comes from the ID in every reader, ext4 included), and a forged ID is rejected at once (`ErrNotFound`) without a directory search or spending the directory read budget | `TestForgedEntryFieldsAreIgnored`, `TestForgedDirentIDsAreRejectedQuickly` (FAT), `TestExfatOpenAndIDs` (exFAT), `TestOpenAndReadDirIgnoreForgedEntryFields` (ext4) |
| The warning collector never loses the size of what it dropped. After `MaxWarnings` distinct messages every further message is counted (saturating at the largest uint64), element `MaxWarnings` of `Info().Warnings` is `SuppressedNote(n)` (`further warnings suppressed: N occurrences not recorded`), the list never exceeds `MaxWarnings+1` entries, an analysis audits the note once (not counted in `Summary.FSWarnings`) and writes the final count to `analysis.end`/`analysis.error` as `fs_warnings_suppressed`; a note-shaped text anywhere but index `MaxWarnings` of a list longer than `MaxWarnings` is an ordinary warning | `TestWarningsCountsSuppressed`, `TestAnalysisAuditsSuppressionNoteOnce`, `TestAnalysisEndCarriesSuppressedFilesystemWarnings` |
| Filesystem anomalies found during an analysis are written to the audit log as `analysis.warning`: source `filesystem-open` for those present when the filesystem was opened, `filesystem` for later ones, each once; they are counted separately from skipped files and are written even when the analysis fails | `TestUnallocForwardsFilesystemWarnings`, `TestExtractForwardsFilesystemWarningsOnce`, `TestFilesystemWarningsAreCountedNotSkipped`, `TestFilesystemWarningsReachAuditWhenAnalysisFails` |
