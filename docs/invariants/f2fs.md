# Invariants: F2FS reader

Covers the F2FS reader `internal/filesys/f2fs` and its builder `f2fstest`. The rules every reader shares are under [filesystems](filesystems.md); deleted-file recovery is under [recovery](recovery.md). Part of the [forensic invariants](../invariants.md), which say how to add or change a row. Each row is enforced by the tests it names: keep them green.

| Invariant | Test |
|---|---|
| In any F2FS directory `Lookup` never says not found about a directory it did not read to the end; in a casefold directory it scans the whole directory and decides in the same order as the ext4 reader (exact, the `~raw~`/`~enc~` alias with two or more records `ErrAmbiguous`, the incomplete-scan error (`filesys.ErrLimit` for the entry cap, else a corruption error matching `filesys.ErrIncomplete`, when the scan did not read the whole directory: entry cap, damaged block map, a dentry block another directory owns or this one maps twice, damaged dentry slots, an unreadable block, `i_size` above 64 MiB, the read budget spent after the first block; a hole is not a cut), exactly one name the kernel's comparison calls the same, `ErrAmbiguous` for two or more keeping at most two records, `ErrUndecided` when a stored name has a shape the comparison was not measured for and nothing above decided, never `ErrNotFound`, not found); `.` and `..` are never folded, an encrypted directory is exact-only, a component over 255 bytes is absent, and a volume whose `s_encoding` (superblock offset 2758) or `s_encoding_flags` (2760) is not implemented gives `ErrUnsupported` on a miss; every row of `kernel-vectors.json.gz` resolves in the committed `f2fs-casefold` image as the kernel resolved it (the image is checked by these tests, not by `TestF2FSMatchesOracle`); the `FuzzF2FSOpen` seeds stay within the fuzz engine's limit | `TestCasefoldLookupMatchesKernel`, `TestSuperblockEncodingFields`, `TestCasefoldFixtureTreeEqualsOracle`, `TestCasefoldPlainDirectoryIsExact`, `TestCasefoldExactBeatsFold`, `TestCasefoldAliasBeatsFold`, `TestCasefoldAliasBeatsASingleFoldHit`, `TestCasefoldAmbiguousIsAnError`, `TestCasefoldExactAfterManyFoldHitsWins`, `TestCasefoldAliasLastStillBeatsFold`, `TestCasefoldTwoAliasRecordsAreAmbiguous`, `TestCasefoldAmbiguityScanIsBounded`, `TestCasefoldUnknownShapeIsUndecidedNotNotFound`, `TestCasefoldUnknownEncodingIsUnsupported`, `TestCasefoldNeverFoldsEncryptedOrDots`, `TestCasefoldInvalidUTF8ComparesBytes`, `TestCasefoldLookupIsBounded`, `TestCasefoldIncompleteScanBeatsFoldDecision`, `TestCasefoldEveryCutBeatsFoldDecision`, `TestCasefoldExactBeforeCutStillWins`, `TestCasefoldExactAndAliasAfterTheCutStillWin`, `TestLookupAfterCapIsAnError`, `TestLookupAtExactlyTheCapIsNotCut`, `TestLookupInDamagedBlockMapIsAnError`, `TestLookupSkipsSharedDentryBlockAndSaysSo`, `TestLookupWithDamagedDentrySlotsIsAnError`, `TestLookupInOversizeDirectoryIsAnError`, `TestLookupAfterUnreadableBlockIsAnError`, `TestLookupAfterIOErrorIsAnIOError`, `TestLookupErrorIsNotCached`, `TestLookupWithoutDamageStaysNotFound`, `TestLookupBudgetCutKeepsItsError`, `TestLookupCutErrorNamesTheCause`, `TestEveryDirectoryCutCauseLogsItsWarning`, `FuzzF2FSLookup`, `TestImageCutDirectoryExitsNonZeroAndIsAudited` (ext4 and F2FS through the command line), `TestFuzzF2FSOpenSeedsFitTheEngine` |
| The F2FS reader equals an independent oracle for each committed `mkfs.f2fs`+`sload.f2fs`-built fixture (`f2fs-extra-attr`, built with `extra_attr,inode_checksum,sb_checksum,inode_crtime`, and `f2fs-default`; oracle from the source tree and the reports of `fsck.f2fs`, `dump.f2fs` and `blkid` on the finished image, which the generator cross-checks against each other): the image's sha256 equals the oracle's `generator.image_sha256` (a stale oracle fails); `Info` (type, label, uuid, block size, size, feature list) equals the oracle with no warnings; the superblock geometry (block and segment counts, area start addresses, root/node/meta inode numbers, feature bits) and the chosen checkpoint (version, flags, pack size, block counts, free segments, next free nid, version-bitmap sizes) equal the tools' values; the NAT block address of the root and of every inode equals `dump.f2fs -n`, and each inode's type, permission bits, size and mtime equal the source tree; the live tree is exactly the oracle's path set (none missing, none extra) with the oracle's types, permission bits, sizes and mtimes; every file's SHA-256 and every symlink target equal the source tree; every file's runs equal, in logical order, the data-block extents `fsck.f2fs` reports (a file held inline has no runs; the oracle must hold a fragmented file); and `Unallocated` equals exactly the free main-area blocks of the SIT bitmaps (the same runs, the same count, no run overlapping a live file's data runs or an inode's node block), with no warning after the full read | `TestF2FSMatchesOracle` |
| F2FS deleted dentries are listed and flagged `Deleted` (names only, no content), each with the ID `dentry:<directory nid>:<block>:<slot>` and, while the NAT still maps its inode, described by it (type, size, attribute `inode`); an entry whose inode now belongs to another directory (`i_pino`) carries `inode_reused=true`, one whose inode is not in the NAT carries `inode_unreadable=true` (size 0, mode 0); a multi-slot deleted name is skipped as a whole; implausible names (NUL or '/') are never listed; a deleted entry is never found by `Lookup` (`ErrNotFound`) and `Open`/`ReadDir` of it is `ErrDeleted`; deleted entries may use at most half of the per-directory entry cap, so at least half of it is always available to live entries (entries are listed in on-disk order); a clean listing raises no warning | `TestReadDirFlagsDeletedEntries`, `TestDeletedSlotSkipsPastName`, `TestDirEntryCapPrefersLiveEntries` |
| F2FS entry IDs are `nid:<canonical decimal>` (a live inode) or `dentry:<directory nid>:<block>:<slot>` (a deleted slot); any other spelling (leading zero, sign, space, hex, wrong prefix or field count, out-of-range number) is `ErrNotFound`, and `Open`/`ReadDir` ignore every other caller-supplied `Entry` field: a forged `Size`, `Type`, `Deleted`, `Encrypted`, name, link target or attribute (`compressed`, `inline`) changes nothing, a directory forged as a file and a compressed file forged as plain stay `ErrUnsupported`, and a deleted slot forged as live stays `ErrDeleted` | `TestOpenIDsAndTypes`, `TestForgedEntryFieldsAreIgnored` (F2FS and FAT), `TestReadDirIgnoresForgedEntryFields` |
| F2FS journals and checkpoints are read as the kernel does, and a structure that cannot be trusted is never believed. The NAT and SIT journals in the checkpoint's summary (full or compact) override the NAT and SIT blocks (NAT: the first journal entry for a nid wins; SIT: a later entry replaces an earlier one); a journal whose entry count exceeds what fits in its block is not interpreted: an over-count NAT journal is ignored with a warning that file locations may be stale, an over-count or unreadable SIT journal means `Unallocated` reports no free space (with a warning), never guessed free space; a SIT entry for a segment outside the main area is ignored with a warning; a segment whose valid-block count is below its bitmap's set bits is reported from the bitmap with a warning; one whose count exceeds its set bits, or claims more valid blocks than a segment holds, is skipped (never reported free) with a warning. Of the two checkpoint packs the valid one with the highest version is used (checksums, the last block's version and `checksum_offset` all verified): an invalid newer pack falls back to the older valid one with a warning, two invalid or two blank packs fail `Open` with `ErrCorrupt`, a blank second pack (what `mkfs.f2fs` leaves) is silent while a blank first pack warns of a possible rollback, a last checkpoint that is not an unmount checkpoint warns that later data is not reflected, and the backup superblock is used (with a warning) only when the primary is bad | `TestNATJournalOverridesBlock`, `TestNATJournalFullAndOverfull`, `TestNATJournalDuplicateNidFirstWins`, `TestNATJournalCompactSummaryManyEntries`, `TestSITJournalOverridesBlock`, `TestSITJournalHostile`, `TestUnallocatedUnreadableSIT`, `TestSITInconsistentEntries`, `TestUnallocatedNeverFreesUsedBlocks`, `TestCheckpointPicksHigherValidVersion`, `TestCheckpointFallsBackToOlderValidPack`, `TestCheckpointBothInvalidIsCorrupt`, `TestBlankPackHandling`, `TestBlankSecondPackIsSilent`, `TestUncleanCheckpointWarns`, `TestSuperblockBackupUsedWhenPrimaryBad` |
| An F2FS file whose node chain is damaged (a cycle, a node that is really an inode, a free node, an address outside the main area, a node or run count past the cap) opens with the bytes that can be trusted (a warning; the tail reads as `ErrCorrupt`, never zeros); a node whose footer names another owner is only warned about; a data-block I/O error is an I/O error, never a corruption verdict; and `File.Runs` reproduce the content byte for byte | `TestBrokenChainsKeepTrustedPrefix`, `TestNodeChainCycleIsCorrupt`, `TestRunCapIsCorrupt`, `TestDataAddrOutsideMainIsCorrupt`, `TestNodeFooterOwnership`, `TestRunsReproduceContent`, `TestDataIOErrorIsNotCorruption` |
