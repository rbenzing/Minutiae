# Architecture rules

The dependency rule is enforced by `TestArchitectureDependencyRule` (`internal/archtest`); the purity, single-writer and recovery rules by the other archtest tests named below.

## Dependency rule
- `internal/evidence` and `internal/version` import no other Minutiae package except `evidence → version`. `internal/evidence` also imports `golang.org/x/text` (NFKC, case folding and the diacritic rule of the full-text normalization, `ftsnorm.go`); its module version is a constant of `FTSNormVersion`, tied to `go.mod` by `TestXTextVersionMatchesGoMod`.
- `internal/device` imports only `evidence`, `version`.
- Backends (`transport/serial`, `protocol`, `android`, `ios`) import only `device`, `evidence`, `version` and their own sub-packages; never `cli`, never each other.
- `internal/android/adb` imports no Minutiae package.
- `cmd/minutiae` imports only `internal/cli`.
- Parser packages `internal/image`, `internal/volume` and `internal/filesys` import no Minutiae package (the one exception: `internal/image` may import its own sub-package `internal/image/ewf`): they work on `io.ReaderAt` and can never write to a case, so they never import `evidence`.
- `internal/image/ewf` (the EWF/E01 reader) and its test builder `internal/image/ewf/ewftest` import no Minutiae package at all (`ewftest` does not even import `ewf`, so the builder is an independent oracle for the reader); the reader works on `[]ewf.Segment` (an `io.ReaderAt` plus a size), so it can never write to a case and tests and fuzzers feed it in-memory bytes.
- Parser test helpers (`volume/volumetest`, `filesys/fstest`) import only their parent package; `internal/filesys/detect` imports only `filesys` and the filesystem packages it probes (today `filesys/apfs`, `filesys/f2fs`, `filesys/ext4`, `filesys/exfat`, `filesys/hfsplus` and `filesys/fat`); each of those imports only `filesys`, and its test builder (`apfs/apfstest`, `f2fs/f2fstest`, `ext4/ext4test`, `exfat/exfattest`, `fat/fattest`, `hfsplus/hfsplustest`) only `filesys` and its parent package. The APFS reader (`internal/filesys/apfs`) also imports `golang.org/x/text` (`norm`, `cases`, `rangetable`) for its name hash and normalization-insensitive lookup, and its builder `apfstest` imports no Minutiae package at all today (it carries its own Fletcher-64, name-hash and Unicode recipe, so it is an independent check on the reader; the architecture test would still allow it `filesys` and `apfs`). APFS snapshot support reaches `examine` and `cli` only through the optional interfaces `filesys.Snapshotter`, `filesys.SnapshotViewer` and `filesys.EncryptedFile` and the sentinels `filesys.ErrNeedsVolume` and `filesys.ErrAmbiguous`, never by importing `apfs`. `internal/filesys` also defines the optional interface `XattrReader` (extended-attribute values), implemented by `apfs`, `hfsplus` and `ext4` (the ext4 reader lists and opens attributes from the inode, the xattr block and EA inodes, and marks an attribute whose EA-inode value fails its hash with `Xattr.Integrity`), found with `filesys.As` like the other optional interfaces; a reader implements only what it can prove. `internal/filesys/decmpfs` (the shared transparent-compression decoder) imports only `filesys`; it holds the header parser, the typed errors and the zlib decoders for types 3 and 4 (`decmpfs.Open`). `hfsplus` imports it (and `apfs` will, in a later task), never each other.
- `internal/filesys/utf8fold` (the Unicode 12.1.0 case-folding and normalization tables the Linux utf8 module uses for casefold directories, generated by `TestGenerateTables` from the committed data files) imports no package at all; only `filesys/ext4` and `filesys/f2fs` may import it; their test builders (`ext4test`, `f2fstest`) do NOT, so a builder stays an independent check.
- `internal/examine` is the only bridge between the parsers and the case: it imports `evidence`, `version`, `device`, `image`, `volume`, `filesys` and `filesys/detect`. It still imports no `internal/records` (`TestRecoveryDependencyEntries`), and no non-test file of it selects a write-capable `os` identifier or imports `io/ioutil` (`TestRecoveredBytesReachDiskOnlyViaNewArtifact`): recovered bytes reach disk only through `evidence.Case.NewArtifact`. Only `internal/evidence` and `internal/examine` set a `Source` kind to a recovered kind (`TestRecoveredKindsOnlyWrittenByEvidenceAndExamine`).
- `internal/evidence/evidencetest` (case, image and recovered-artifact fixtures, `RequireProblem`/`RequireNotice`/`RequireClean`, `RewriteManifest` and the other named tamper helpers for the tests of `internal/evidence` and of the layers above it) imports only `internal/evidence` (it cannot be `recordstest`, which imports `records` and would make an import cycle). It is test-only like `recordstest` and `filesys/fstest`: no non-`_test.go` file may import any of the three (`testOnlyPackages`, `TestTestOnlyPackagesAreImportedFromTestsOnly`).
- Composition rule: a layer above `internal/evidence` that owns a check `evidence` cannot make (the byte reproduction of recovered artifacts needs `image`, so it lives in `examine`) adds it to `case verify` through `Case.VerifyWith(ctx, checks...)` (`examine.RecoveredCheck`); `examine.VerifyChecks()` is the one list of composed checks (R6, R9, R10) the command line passes; the checks run after the built-in ones, can only add problems, notices and counters, and the one `verify.run` audit entry covers all of them (`TestVerifyRunAuditCoversComposedChecks`). `filesys` optional capabilities (`Recoverer`, `Journaler`, `AllocatedRunner`, `XattrReader`) are reached through `filesys.SupportsRecovery`/`filesys.As`, never by a type assertion, so wrappers (`SafeFS`, the warned filesystem) forward them through `Underlying()`.
- `internal/records` (the unified artifact database: record model, type registry, audited batch writer, ingest lifecycle, reader) imports only `evidence` and `version`; `internal/records/recordstest` (case and artifact fixtures, record generator, `NewV1Case`, the named tamper helpers) imports only `records` and `evidence`. Parsers (sub-project 4) will import `records`, never SQLite. `recordstest` is test-only: no non-`_test.go` file may import it, so it can never be linked into the binary (`TestTestOnlyPackagesAreImportedFromTestsOnly`, with a self-test that the rule flags a violation, `TestTestOnlyRuleFlagsNonTestImport`).
- `internal/sqlitefile` (the SQLite file library of sub-project 3, plan 3I: pages, freelist, WAL, rollback journal, `Live()`, `History()`; it also exports the recovered-row locator `RecoveredLocator` and the claim predicate `Schema.ClaimMatch`, so the generic and the typed recovery share one implementation of each) imports no Minutiae package (the architecture test lists it with no allowed import), no SQL engine or driver and not `database/sql` in any non-test file (`TestSQLiteFileUsesNoEngine`), and by convention, checked in review, no `os` and no clock: it works on `io.ReaderAt` and can never write to a case or to evidence. `modernc.org/sqlite` stays the driver of `artifacts.db` (in `internal/evidence`) and, in `_test.go` files only, the independent test oracle. The 4A purity tests (`pure_test.go`) cover this package as its own class `pcSqlitefile` (ruling C54): the same bans as the parser classes (no printing, clock, time zone, goroutine, SQL; a method named `Local` is refused, hence `Cell.LocalBytes`), the same P5 rule (no package-level state beyond constant tables, sentinels and regexps) with ONE named exception, the test hook `pureHook` in `guard.go` (`TestPureHookIsTheOnlyAllowedPackageVar`), and an import allowlist that adds `sync`, `sync/atomic`, `container/list`, `cmp` and `crypto/sha256` for this class alone (instance-scoped caches and locks, deterministic, no clock, goroutine or I/O; `TestPurityAllowlistSelfTest` shows `sync` and the rest still refused in the parser, decode and parse classes). `runtime` is refused: a `PanicError` carries the recovered value only, no stack.
- `internal/sqlitefile/sqlitetest` (independent encoders: databases, WALs, rollback journals, freelists, pointer maps; the builder the library's tests write their files with) is a test-only package: it imports no Minutiae package at all today (not even `sqlitefile`, so it is an independent check on the reader; `TestArchitectureDependencyRule` would still allow it `internal/sqlitefile`, so the independence is kept by review, as for `apfstest`), is held to the real engine by `TestBuilderMatchesEngine`, `TestBuilderWALMatchesEngine` and `TestBuilderJournalMatchesEngine`, and no non-test file may import it (`TestTestOnlyPackagesAreImportedFromTestsOnly`).
- Single-writer rule (enforced by `TestOnlyRecordsPackageWritesRecordTables`): no package other than `internal/records` (and the schema code in `internal/evidence`) executes SQL that writes the record tables or `artifacts`; every record reaches `artifacts.db` through the audited `records.Writer`.
- `internal/dbrecover` (sub-project 3, plan 3J: the typed recovery run that turns the rows of `internal/sqlitefile` into `db_row` records) imports only `evidence`, `records` and `sqlitefile` (`TestArchitectureDependencyRule`), no `parse`, no parser and no SQL engine; no parser or record-type package names the `db_row` record type (`TestDBRowTypeStaysOutOfParsers` scans `internal/parsers` and `internal/recordtypes`), opens case artifacts read-only, and writes only through the audited `records.Writer` and `Case.NewArtifact` (`TestRecoveredBytesReachDiskOnlyViaNewArtifact` scans its non-test files for `os` writes).
- `internal/decode/sqlitedb` (the SQLite table decoder, sub-project 4, plan 4B) imports `internal/sqlitefile`, `internal/parse` and `internal/records` (`Range` only); it is purity class `pcDecode` (no `sync`: `DB`, `Table`, `Index` and `Context` are single-goroutine). `modernc.org/sqlite` and `database/sql` appear only in its `_test.go` files, as an oracle on COPIES. `internal/sqlitefile` now also exports the engine-equality key (`EqualityKey`, `CanonicalCollation`, `ColumnCollation`) for the decoding layer.
- Artifact parsers (sub-project 4, plan 4A). Import table: `internal/parse` (the contract: `Parser`, `Input`, `Emitter`, `Limits`, `SealedReaderAt`) imports `records` for data types only; `internal/recordtypes/common` imports no Minutiae package; `internal/recordtypes/<t>` imports `records` (`SetValidator` only, in `init` only) and `common`; `internal/recordtypes/all` imports the type packages; `internal/parsers` imports `parse`, `records` (registry reads only) and, for the compiled-in registry, each parser package (`internal/parsers/androidmms`, `internal/parsers/androidcalllog`, `internal/parsers/androidcontacts`, `internal/parsers/ioscalls`, `internal/parsers/iosaddressbook`, `internal/parsers/chromium` and `internal/parsers/safari` so far); `internal/parsers/parsertest` is test-only (its oracle kit also imports `internal/decode/sqlitedb`, `internal/decode/sqlitedb/recrun`, `internal/decode/sqlitedb/rowrun` and `internal/sqlitefile`; the recover kit drives the typed recovery runner over a fixture); `internal/artparse` (the host: discovery, sandbox, emitter, run, plan, the backup resolution step `ResolveBackups` of plan 4E, and the typed recovery pass `RecoverTyped`) imports `evidence`, `version`, `records`, `parse`, `recordtypes/all`, `decode/iosbackup`, `decode/sqlitedb`, `decode/sqlitedb/recrun` (the typed pass runs the decoder inside the job sandbox) and `dbrecover` (for `LocatorDigest` alone: the one digest of a recovered row's locator, so the host and the generic run agree on which rows the typed pass left); `internal/parsers/androidmms` (plan 4D, a pure parser) imports `parse`, `records`, `recordtypes/common`, `recordtypes/message`, `decode/sqlitedb` and `decode/sqlitedb/rowrun`; `internal/parsers/androidcalllog` (plan 4D, a pure parser) imports `parse`, `records`, `recordtypes/common`, `recordtypes/call`, `decode/ts` and `decode/sqlitedb/rowrun`; `internal/parsers/androidcontacts` (plan 4D, a pure parser) imports `parse`, `records`, `recordtypes/common`, `recordtypes/contact`, `decode/sqlitedb` (for the typed `ErrNoSuchTable` and `UnsupportedSchemaError` of a join) and `decode/sqlitedb/rowrun`; `internal/parsers/ioscalls` (plan 4E, a pure parser) imports `parse`, `records`, `recordtypes/common`, `recordtypes/call`, `decode/ts`, `decode/sqlitedb/rowrun` and `decode/sqlitedb/cellx`; `internal/parsers/iosaddressbook` (plan 4E, a pure parser) imports `parse`, `records`, `recordtypes/common`, `recordtypes/contact`, `decode/sqlitedb`, `decode/sqlitedb/rowrun` and `decode/sqlitedb/cellx`; `internal/parsers/chromium` (plan 4F, a pure parser) imports `parse`, `records`, `recordtypes/common`, `recordtypes/web`, `decode/ts` and `decode/sqlitedb/rowrun`; `internal/parsers/safari` (plan 4F, a pure parser) imports `parse`, `records`, `recordtypes/common`, `recordtypes/web`, `decode/ts`, `decode/sqlitedb`, `decode/sqlitedb/rowrun` and `sqlitefile` (for `ErrBudget` only); `internal/decode/sqlitedb/cellx` (plan 4E, numeric cells and Apple-epoch instants, kept apart from `rowrun` so the Android parser hashes do not change) is a decode-class leaf that imports `decode/sqlitedb`, `decode/sqlitedb/rowrun`, `decode/ts` and `parse` only, and the iOS parsers use it beside `rowrun`; `internal/decode/sqlitedb/rowrun` (plan 4D, the mapping runner and cell helpers every SQLite parser uses) is a decode-class leaf that imports `decode/sqlitedb`, `decode/ts`, `parse` and `records` only (the archtest table pins it); parser packages import `rowrun`, `recordtypes/*` and `parse`, plus `decode/sqlitedb` for its typed error sentinels (androidmms and androidcontacts) and `decode/ts` (androidcalllog), and `internal/parsers` imports the parser packages as the registry list; `tools/parserhash` imports `parse` and `parsers`; `internal/cli` reaches the host through `artparse`, and uses `internal/parse` (limits and platform constants) and `internal/parsers` (the registry and its hashes) for what the commands show. Threat model: the parsers are trusted in-repo code, the DATA they read is hostile; a malicious parser author is out of scope. Purity rules (enforced by the architecture tests, each with a self-test): parser packages import only the stdlib allowlist table in the test (`encoding/xml` is admitted for the decode class alone), use no `fmt` printing, `log`, `os`, `runtime`, clock, time zone, goroutine, finalizer, `import "C"` or assembly (syntax-tree bans), may use only the allowlisted selectors of `records` (data types, never `NewWriter`, `RegisterType` or `SetValidator` outside a `recordtypes` `init`), have no non-Go source in their directories, and hold no package-level mutable state (only blank assertions, error sentinels, regexps, read-only tables and `common.Schema` values).
- Typed recovery runner (plan 4G): `internal/decode/sqlitedb/recrun` is a decode-class leaf (purity class `pcDecode`) that imports `decode/sqlitedb`, `decode/sqlitedb/rowrun`, `parse`, `records` and `sqlitefile` only (the archtest table pins it; it is the one decoder besides `sqlitedb` allowed to import `sqlitefile`, because it consumes `sqlitefile.RecoveredRow`). It drives a parser's `parse.TableMapping`s over `sqlitedb.DB.ClaimedHistory` rows rebuilt with `FromRecovered` and hands every record to a `parse.RecoveryEmitter` with the `parse.RecoveredFacts` computed from the row; it never stamps recovery facts on a record (the host does) and never calls the live `Emit`. Its source is part of every claiming parser's `.recover` identity (`parsers.RecoveryRunnerPath`, pinned to the package of `recrun.Report` by `TestRecoveryRunnerPathIsTheRunnerPackage`).
- Decoders (sub-project 4, plan 4C): `internal/decode/ts`, `internal/decode/plist` and `internal/decode/typedstream` are leaf packages: they import no Minutiae package (their `allowed` entries in `TestArchitectureDependencyRule` are empty), work on bytes and values, and can never write to a case. They form the purity class `pcDecode` (the parser bans: no printing, clock, time zone, goroutine, SQL; no package-level state beyond sentinels, regexps and read-only tables), which also admits `encoding/binary`, `encoding/hex`, `io`, `context`, `embed` and, for decode alone, `encoding/xml`. The one backend edge is `internal/ios/mb2` to `internal/decode/plist` (`TestBackendsImportDecodeOnlyThroughMb2`). All three are listed in `purityRequired` (internal/archtest), so a rename cannot drop one from the scan.
- iOS backup reader (plan 4E): `internal/decode/iosbackup` reads the `Files` table of a backup's `Manifest.db` and the `IsEncrypted` key of its `Manifest.plist`. - `internal/cli` may import anything.
- `tools/fuzzcampaign` (L120, plan LX-8) imports no Minutiae package, runs fuzzers only in a throwaway copy of the source (never in the working tree) and, in docker mode, only with a host-made copy that excludes `cases/` and every untracked file.


## The case database has one connection (one exception: case verify)
- Rule: `artifacts.db` is reached through ONE connection (`openDB`: `SetMaxOpenConns(1)`; every `ReadTx` and `StoreTx` queues on it, nesting is refused). Every pragma that protects the evidence (foreign keys, recursive triggers, rollback journal, full fsync, `temp_store = MEMORY`) is applied to that connection by the connector, and no statement ever meets another transaction.
- Exception (5D Task 15c, `internal/evidence/verify_readers.go`): `case verify` opens, for the record part of its own run, a small pool (at most 3) of additional READ-ONLY connections to `artifacts.db`, so that P10 (`records.integrity_check`, 55% of a 10,000,000-record verify) runs beside the record stream and the index pass and the two full-text tables are decoded together. Rationale: the target verify time cannot be met while the longest phase waits for the case connection.
- Why it is safe: (1) verify holds the case lock for its whole run, so no other process writes `artifacts.db`, and the case connection writes nothing during verify; (2) every pool connection has `PRAGMA query_only = ON` and `temp_store = MEMORY` before it is handed out, the file is opened `mode=rw` (never created), and the pool is used only through `ReadHandle` (one SELECT or WITH statement, no PRAGMA, no ATTACH); (3) the pool lives only inside `verifyRecords` and is closed on every path, a panic and a cancel included, after every goroutine that uses it has returned; (4) nothing else in the code base may open one: the connector is unexported. It is not opened `mode=ro` because SQLite's `integrity_check` on such a connection does not report a row that breaks a CHECK constraint (measured with the bundled modernc.org/sqlite; `TestVerifyIntegrityCheckFlagged` pins the finding), which would weaken P10.
- Guards: `TestVerifyIntegrityCheckConnectionIsReadOnly` (writes refused, the file unchanged, the pool closed), `TestVerifyConcurrentPhasesEqualSerial` (the report is byte-identical to the serial order, `SetVerifyConcurrency(false)`), `TestVerifyConcurrentCancelKeepsFindings`. When the pool cannot be opened verify runs the serial order on the case connection.

## cgo policy (user decision 2026-10-07)
1. cgo is ALLOWED when a capability needs it and no pure-Go route works: decryption (sub-project 10), hooking into a device or host environment (OS or device services, drivers, vendor libraries), and native libraries that reveal artifacts no pure-Go reader can. The capability's spec names the C dependency, its version or pin, its licence, and why pure Go is not enough.
2. Fenced: cgo code lives only in dedicated packages, in `//go:build cgo` files, each with a `!cgo` counterpart that compiles and returns an error wrapping `errors.ErrUnsupported` naming the missing capability. A capability is never silently skipped. `CGO_ENABLED=0` must always build and pass the tests on every OS.
3. The forensic invariants still bind cgo code: bytes reach the case only through `evidence.Case.NewArtifact`/`Capture`; sources are read-only; outputs (for example decrypted data) are DERIVED artifacts with full provenance (method, library and version, where the key came from) and the original (the ciphertext) stays in the case; device writes and hooks follow the device-write rules (explicit permission, audited before the act).
4. Hostile input: Go cannot recover a crash in C code, so a C library that reads evidence or device bytes must be fuzzed through its Go wrapper and contained so a C crash fails that one analysis closed (audited as `analysis.error`) instead of killing the process mid-write. The default is a helper subprocess; the capability's spec states the containment.
5. Rule P4 (no non-Go source and no cgo in `internal/image`, `volume`, `filesys`, `records` and the parsers) STAYS. A parser that needs a C library gets it through a dedicated cgo package, behind an interface its spec defines. The architecture test gains an allow-list entry per cgo package when one is added (none exists yet).
6. Builds: a pure-Go (`CGO_ENABLED=0`) static binary stays available on every OS and is the default release; a cgo-capable build is per OS, where a C toolchain exists. The release command sets `CGO_ENABLED` explicitly.
